## Ролик между цифрами (полуповорот)
- Движок (`halfFix` в engine.js) разбирает окно на ролики по светлому: полоса окна по высоте (где много тёмного), светлое —
  ярче окрестности, промежутки и кромки рамки прочь, наклон ряда выправляется. Ролик на переходе — два куска с пустой полосой
  (низ цифры d сверху, верх d+1 снизу) или один кусок у края окна. Пару (d, d+1) узнаём по шаблонам: цифры соседних роликов
  (тот же шрифт) и цифры шрифтов браузера (`TPL_FONTS`: узкий, Arial/Helvetica, DIN), строгий Dice, сжатие у краёв окна.
  Принимаем при sc ≥ 0,5 и отрыве от второй пары ≥ 0,03, иначе «?» (человек допишет): на чужом шрифте так нет уверенных ошибок.
  Результат — `drums[].half: [{i, d, sc, margin, rank}]`, `TeploWater.fromDrum` → `half: true, pair: [[d, d+1]]`.
- `water.html`: `curve` — ролик-цилиндр (цифры у краёв окна сжаты), `halfs: [...]` — перенос (239→240: два ролика на переходе),
  `font` — другой шрифт цифр.
- `water_half.json` — 17 случаев (все пары 0|1…9|0, тёмные/светлые окна, цилиндр, наклон, издалека, перенос, с прошлым и без).
  На 02.11.2026 — 17/17 (было 5/17). `water_half_fonts.json` — 12 случаев шрифтами Liberation/FreeSans/Inter/Mono/Carlito:
  9/12, промахи — «?», не чужая цифра. Как на телефоне (нет шрифта лаборатории):
  `TPL_FONTS='["\"Liberation Sans\", sans-serif"]' node run.cjs water_half.json` — 17/17, шрифты — 8/12.
- `node half.cjs water_half.json` — что узнано по каждому случаю (пара, sc, margin, rank) — для подбора порогов;

## Проход по ЖК и сдвинутый ролик (engine v=12, 02.11.2026)
- **Проход по ЖК** (`lcdPass` в engine.js): главное число экрана (или одна «E» экрана кода) нашлось, а подписи рядом нет —
  приближаем сам экран (цифра ≈ 200 px) и ищем текст ещё раз, как есть и с локальным контрастом (`detect({local})`).
  Новое добавляется в `lines` с `lcd: 1`; на экране кода «E» и прочерки склеиваются в одну рамку ряда и читаются целиком
  («E---....» / варианты «E-------»), строка «e» заменяется. Значки: «m³» → «ni», «m'», «m)», «mi»; «m³/h» у Sharky —
  «m» над «h» (`ocrparse`: всё это — тег `m`, «h»/«n» под ним → расход, иначе явное «m³» → объём, неясное «m» — по длине числа).
  Осколок с кнопки («7» под наклоном) рядом с числом из ≥ 3 цифр — не показание. Отладка: `window.TEPLO_LCD_LOG = 1`.
- **Сдвинутый ролик** (`halfFix` → `readCell`): ролик «между цифрами», где один кусок ≥ 75 % высоты цифры, — не переход,
  а люфт (NOVATOR: «5» опущена на четверть, сверху хвост «4»). Такой кусок вырезаем и читаем распознавателем (inv/bin/plain,
  цифра в двух из трёх) → обычная цифра, `drums[].shifted: [{i, d}]`; не прочиталась — пара по шаблонам или «?», как раньше.
- Живые фото из /admin (только локально, в git не класть): `IMG_DIR=<папка> node heat.cjs real_heat.local.json` — 11/11
  (Sharky 774: часы, «E-------», мощность, объём, подача, расход, тест экрана, энергия, dt; 2 электросчётчика → не тепло);
  `IMG_DIR=<папка> node run.cjs real_water.local.json` — NOVATOR 00502 (+310) → 502 и без прошлого, и с прошлым 495.
  Фото скачиваются из /admin: `GET /api/admin/photos` → `GET /api/admin/photo?id=…` (вход тестовой учёткой).
