# teplo_test — правила работы (читать в начале каждой сессии)

## Где живёт и как попадает на сервер
- Репозиторий github.com/egfel00-cmyk/teplo_test, ветка main. Корень репозитория = корень сайта.
- Сервер pokabot (Hetzner, за Cloudflare Tunnel — ingress в /etc/cloudflared/config.yml на сервере) подтягивает main раз в минуту
  (`/srv/sites/teplo_test`). Адрес: **https://peredai.com.ua/** (свой домен с 06.11.2026, SITE_BASE=''); старый
  https://pokabot.xyz/teplo_test/… отвечает 301 на новый.
- Всё запушенное в main через минуту на бою. Коммитить и пушить сразу и автоматически — не ждать команды.
- Доступа к серверу у сессий НЕТ (ни SSH, ни панели). Всё серверное — только кодом в репозитории. Настройку сервера
  (Caddy, PHP, база) меняет владелец одной командой: sudo bash /srv/app/tools_site_add.sh teplo_test [--domain …].
- После пуша — проверить на бою (через 1–2 мин): curl -s -o /dev/null -w '%{http_code}' https://peredai.com.ua/…
  Если прокси сессии не пускает peredai.com.ua (нет в разрешённых доменах) — GET через WebFetch (JSON, напр. /api/health) или
  встроенный браузер владельца (если чат связан с его компьютером); pokabot.xyz/teplo_test/… теперь только 301.
  WebFetch открывает только адреса, которые есть в сообщении владельца: блок продолжения сессии заканчивать строкой
  `https://peredai.com.ua/api/health https://peredai.com.ua/api/config https://peredai.com.ua/admin` (59-я: без неё сайт был недоступен).

- **Разрешение владельца — заранее, на каждую сессию (07.11.2026)**: доступ к сайту проекта (peredai.com.ua: /api/health,
  /api/config, /api/vk/status, /admin и любые GET) и к старому pokabot.xyz — разрешён всегда; НЕ спрашивать владельца и не ждать
  его подтверждения. Разрешение записано в `.claude/settings.json` (permissions.allow: WebFetch этих доменов, `php tests/rev.php`).
  Если среда всё равно показывает запрос одобрения — это настройка приложения, не вопрос к владельцу: не писать ему «разрешите»,
  а сверять бой тем, что доступно, и отметить в ПРОДОЛЖЕНИЕ. Нужен ещё домен/команда для проекта — дописать в этот же файл.
- **/admin — по умолчанию, без вопросов (08.11.2026, владелец: «не заёбывай подтверждениями»)**: входить на сайт и в /admin
  (учётка admin@teplo.test; в Chrome владельца он уже залогинен) сразу, когда это нужно для задачи — журнал, ошибки, платёжки,
  настройки. Владельцу про доступы и подтверждения не писать вообще; всё делать максимально без его участия. Не вышло зайти
  (браузер не подключён/спит) — сделать, что можно без него (WebFetch, /api/health, код), и отметить в ПРОДОЛЖЕНИЕ.
  Исключение одно: секреты (токены, пароли) в поля не вводить — их вставляет владелец; бота меняет и пересылкой сообщения
  @BotFather текущему боту (Telegram::botFromChat).
- **Браузер и сеть из облака (09.11.2026, 78-я)**: своего браузера у сессии нет — прокси среды отвечает 403 на rada.info, *.gov.ua,
  peredai.com.ua, google; Chromium в среде получит то же (он — только для локального сайта). Без владельца: WebSearch + WebFetch, а файлы
  (pdf/xlsx/jpg), найденные на страницах, — полными ссылками в конец блока продолжения, чтобы владелец вставил их сообщением.
  Чат открыт в desktop-приложении на Mac → его shell (`device_bash`, curl с украинского адреса) и встроенный браузер. Обходы прокси не строить.
  **79-я**: даже по ссылкам владельца WebFetch не читает xlsx, PDF-сканы и jpg rada.info, а nem-rada.gov.ua зацикливает https→http — такие файлы только через
  desktop-приложение (`device_bash` → curl → `device_stage_files`). Мост «not connected» — файлы отложить, не повторять попытки.
  **119-я**: Facebook в Chrome владельца не открывать — пост громады повесил вкладку, расширение отключилось до конца сессии; суммы — из сниппетов Google и сайта громады.
  WebFetch чужих сайтов, пока владельца нет, — только адреса из выдачи WebSearch (адрес из Google в Chrome → `PROVENANCE_REQUIRED`, повторять нельзя).

## Как устроен сервер для сайта (PHP 8.5, Caddy 2.6, MariaDB 11.8)
- index.php — фронт-контроллер: любой путь, которого нет файлом, уходит в /index.php.
- Адрес сайта: getenv('SITE_BASE') — '/teplo_test' сейчас и '' на своём домене. Ссылки и fetch — ОТНОСИТЕЛЬНЫЕ или через
  SITE_BASE; никаких зашитых '/teplo_test/' и 'pokabot.xyz' — иначе переезд на домен сломает сайт.
- Писать можно ТОЛЬКО в getenv('SITE_DATA') (/srv/sites/teplo_test_data: uploads/, cache/, sessions/, tmp/). Папка кода
  только для чтения. Папка данных наружу не отдаётся — файлы из неё отдавать через PHP.
- База: $cfg = require getenv('SITE_DATA') . '/config.php'; → $cfg['db'] (host, name, user, pass). PDO MySQL, utf8mb4.
  Схему создавать кодом: CREATE TABLE IF NOT EXISTS / ALTER … ADD COLUMN IF NOT EXISTS при первом обращении — руками в
  базу никто не зайдёт.
- Секреты (ключи API и т.п.) — только на сервере, НЕ в git. Ключ Claude API и токен бота владелец вставляет сам в
  /admin → «Настройки» (файл SITE_DATA/uploads/settings/settings.json, 0600, главнее config.php; список — Cfg::RUNTIME).
  Остальное — сказать владельцу, что дописать в /srv/sites/teplo_test_data/config.php.
- cron.php в корне (если есть) запускается раз в минуту от пользователя сайта (SITE_DATA доступна).
- Почта (81-я): `app/mail.php` — свой SMTP по 587 + STARTTLS (Hetzner закрывает исходящие 25 и 465); ящик и ключ владелец вставляет в /admin → «Настройки» → «Пошта»
  (сохраняется только после тестового письма). Сводка владельцу, нагадування на e-mail (отписка `/api/mail/off`), дальше — подача показаний e-mail.
- Снаружи закрыто (404): всё с точкой (.git, .env, .claude), *.md, *.sql, *.sh, *.log, *.ini, копии (*.bak, ~), tests/,
  cases/, vendor/, node_modules/, tools_*, cron.php. Тесты и инструменты класть туда — их не видно.
- multipart/form-data отвергается (415) до PHP, file_uploads выключен (защита от PHP2Shell). Файлы загружать из браузера
  сырым телом: fetch(url, {method:'POST', body: file, headers:{'Content-Type': file.type}}) и php://input; до 24 МБ.
- Запрещены exec/system/shell_exec/proc_open/popen; open_basedir — только папки сайта; 30 с и 128 МБ на запрос.

## Автоподача поставщикам (102-я)
- **Владелец 10.11.2026: «да» на все автоотправки всех коммунальных поставщиков во всех добавленных громадах — и на новые сразу, если есть
  возможность отправлять в фоне.** Отдельного «так» больше не ждать: нашли канал — подключать робота в той же сессии.
- Общий робот — `app/localbot.php` (`LocalBot::BOTS`: `form` — форма без входа (рахунок → страница абонента → показания), `cab` — обычная HTML-форма
  входа без капчи, `mail` — e-mail поставщика со скриньки сервиса); в справочнике `via` = id бота. Подключение = проверка «дойти до формы, ничего не отправить».
  Стенд `tests/lb-mock` (+ `lb_base_<бот>` в config.php), e2e `tests/e2e/e2e_lbot.cjs`. Как добавить — `skills/oblast-providers/SKILL.md`, «Автоподача».
- Не обходим: капчу (в т.ч. невидимую reCAPTCHA), антиспам-токены форм, проверки Cloudflare → `robot: captcha`. Закрытые API из JS-бандлов SPA-кабинетов
  (gkh.in.ua, abon.com.ua и т.п.) не разбираем и демо-учётки из них не используем — только то, что сайт открыто даёт человеку (HTML-формы, e-mail).

## Распознавание фото
- По умолчанию — в браузере человека, бесплатно: web/ocr/engine.js (PaddleOCR PP-OCRv4 + onnxruntime-web WASM, ~30 МБ, грузится
  при первом «з фото»), разбор текста в поля — web/src/ocrparse.js (подписи Gcal/m³/HT/CT/ON/EH, «тени» сегментов,
  десятичная точка по формату модели и прошлым показаниям, счётчики воды/света/газа отсеиваются). CSP страницы — с 'wasm-unsafe-eval'.
- Вошёл — копия фото и итог (POST /api/recognize/local) идут в /admin. Без входа (101-я) — тоже, если человек разрешил аналитику: заголовок `X-Vid`
  (teplo.vid), в базе `user_id = 0` + `vid`, в /admin подпись «Гость XXXX», как в журнале; копия гостя — в `f._gsrv` (не `_srv`: фото истории у гостя локальные). Ключ Claude в «Настройках» необязателен: если задан,
  вошедших распознаёт нейросеть на сервере (платно).

## Как работать
- Перед пушем: php -l на изменённые .php; страницы — открыть локально:
  SITE_BASE= SITE_DATA=/tmp/teplo_data php -S 127.0.0.1:8000 index.php (и посмотреть в браузере/скриншотом).
- Тесты — в tests/ (наружу не видны), только синтетика. Не перебарщивать.
- Отчёты владельцу — кратко по-русски; разрешение на всё — не спрашивать подтверждений.
- Токены, пароли, личные фото/видео/скрины владельца — не в репозиторий.
  Исключение (92-я, по просьбе владельца): `web/img/lp-heat.webp` — кроп только окна ЖК его теплосчётчика для лендинга (без номера квартиры, заводского номера и QR).

## Контекст и переходы между сессиями (обязательно)
- Следить за своим контекстом самому. Как только разговор длинный (много скриншотов/логов, ~70 % окна) или задача
  закончена — НЕ ждать просьбы: закоммитить и запушить всё, обновить `docs/ПРОДОЛЖЕНИЕ.md` (что сделано, что открыто,
  как проверять) и ту же сводку — в документ проекта claude.ai «ПРОДОЛЖЕНИЕ — …», затем дать владельцу в ответе
  блок для копирования: «Продолжи Теплосервис: прочитай CLAUDE.md и docs/ПРОДОЛЖЕНИЕ.md, дальше — <следующий шаг>».
- Не начинать большую новую задачу на исходе контекста — сначала переход.
- Новая сессия: первым делом CLAUDE.md → docs/ПРОДОЛЖЕНИЕ.md → git log -10.
