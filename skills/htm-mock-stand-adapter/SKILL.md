# Стенд mock ХТМ и HtmAdapter (Теплосервис)

Используй при написании или изменении стенда, адаптера отправки показаний в кабинет ХТМ, фоновой очереди отправок, канарейки и dry-run.

## 1. Стенд (`/volume1/web/htm-mock/`)
- Отдельный виртуальный хост Web Station, **только LAN, basic auth, `noindex`, крупная плашка «ТЕСТОВЫЙ СТЕНД» на каждой странице**. Копия страницы входа реальной организации в открытом доступе выглядит как фишинг — наружу никогда.
- Разметку, имена полей, cookie, редиректы и тексты — по снятым фикстурам (`tests/fixtures/htm/...`), 1:1.
- Поведение: оба входа (лицевой счёт + фамилия; email + пароль), правило «после регистрации вход по счёту отключён», несколько квартир, приборы тепла и ГВ, форма показаний, подтверждение, история.
- Переключатель сценариев (админка стенда или заголовок `X-Mock-Scenario`): `ok`, `bad_credentials`, `auth_mode_disabled`, `period_closed` (вне 5–25), `less_than_previous`, `already_submitted`, `session_expired`, `captcha`, `server_500`, `maintenance`, `markup_changed`, `slow`.
- Журнал всех запросов (что прислал адаптер) — для проверок в тестах.

## 2. Адаптер
```php
interface ProviderAdapter {
  public function login(Credentials $c): Session;               // оба режима входа
  public function listMeters(Session $s): array;                // приборы + последнее числящееся показание
  public function submitReading(Session $s, MeterRef $m, Reading $r, bool $dryRun): SubmitResult;
  public function verify(Session $s, MeterRef $m, Reading $r): bool;
}
```
- `HtmAdapter`: cURL + cookie jar на задачу, DOMDocument/XPath, `base_url` из конфига (боевой / стенд), селекторы и маркеры — из `htm-adapter-spec.json`, не хардкодить по коду.
- Формат числа — как требует форма (разделитель, знаки); перед отправкой повторная проверка (`Validator`) с последним числящимся значением из `listMeters`.
- `dryRun`: всё до нажатия «Отправить», сохранить заполненную форму как доказательство.
- Результаты: `ok`, `already_exists`, `auth_failed`, `auth_mode_disabled`, `period_closed`, `rejected`, `captcha`, `site_changed`, `network`, `unknown` — по `provider_message_map`.
- Ни капчу, ни 2FA не обходим: `captcha` → пауза автоотправки и запасной режим.

## 3. Фоновая отправка
Нажал «Отправить» / сработало расписание → `jobs` → адаптер: вход → форма → заполнение → отправка → `verify` по истории → `submissions` (+ evidence HTML/скрин) → уведомление «✅ Принято ХТМ» (бесплатно всем).
Ошибка: сетевые/5xx — повтор с бэкоффом до конца окна (тепло 5–25); «нужен человек» — сразу **запасной режим**: ссылка на кабинет, готовые цифры, пошаговая инструкция. Один вход на задачу, без параллельных сессий, паузы между пользователями.

## 4. Канарейка и dry-run
- Ежедневно: GET страницы входа без авторизации → хэш структуры формы (имена полей, action). Еженедельно: вход своим аккаунтом, открыть форму, без отправки. Изменилось → пауза автоотправки для всех + письмо админу.
- Порядок выхода на боевой: стенд → dry-run своим аккаунтом → одна живая отправка своим аккаунтом в окно → авто для себя → другие пользователи.

## 5. Тесты
PHPUnit: адаптер против стенда по всем сценариям; очередь и повторы; запасной режим; verify; парсинг ответов; формат числа. Секреты в тестах — фиктивные, в логах и трассах секретов нет.
