# Снятие кабинета ХТМ (Теплосервис)

Используй, когда нужно снять или переснять личный кабинет ХТМ (https://www.hts.kharkov.ua/cabinet/login), подготовить промт для Claude в Chrome или разобрать то, что он вернул.

## 1. Промт
Полный текст — в документе проекта «промт для Claude в Chrome — снятие кабинета ХТМ». Если его нет под рукой, собери по этой схеме:
- цель: структура и поведение страниц + проверка, что поля находятся и заполняются; фоновую автоматику потом делает PHP-адаптер на NAS;
- этапы: A без входа (обе формы входа, регистрация, восстановление) → B вход владельцем, навигация до формы и истории, запись сети → D автозаполнение без отправки → C (только в окно приёма тепла 5–25, только по команде) одна настоящая отправка;
- результат: очищенные `htm-page-NN-*.html`, `htm-capture.json`, `htm-adapter-spec.json`, отчёт «можно ли всё чистым HTTP».

## 2. Жёсткие правила (не ослаблять)
- Владелец логинится сам; пароль/фамилия/лицевой счёт не попадают в переписку.
- Без команды ничего не отправлять и не менять; заполнять поля можно, нажимать «Відправити» — нет.
- Заведомо неверные значения не отправлять никогда.
- Одна ошибочная попытка входа максимум, только с разрешения.
- Персональные данные заменять плейсхолдерами (`{{SURNAME}}`, `{{ACCOUNT}}`, `{{EMAIL}}`, `{{METER_SN}}`, цифры показаний и сумм — `9`), значения cookie/токенов — `{{TOKEN len=NN}}`; имена полей и тексты интерфейса — как есть.
- Без GIF; без диалогов alert/confirm.

## 3. Проверка полученного (чек-лист)
- [ ] Обе формы входа: action, method, поля, hidden, маркеры успеха/ошибки; что с входом по счёту после регистрации.
- [ ] CSRF: источник (hidden/meta/cookie), меняется ли на каждом запросе.
- [ ] Cookie сессии: имена, атрибуты, наблюдаемое время жизни.
- [ ] Список приборов: как найти тепло и ГВ, id прибора, последнее числящееся показание (XPath).
- [ ] Форма показаний: поля (тепло, ГВ, дата?, часы ошибки?), разделитель, знаков после запятой, клиентская валидация, тексты ошибок дословно.
- [ ] Результат отправки: маркеры успеха и ошибок (период закрыт, меньше прошлого, сессия истекла).
- [ ] История: где видно принятое показание (для verify).
- [ ] Защита: капча, 2FA, rate-limit, проверка Referer/User-Agent; `requires_js`.
- [ ] Окно приёма: написано ли в кабинете; поведение вне окна.

Чего-то не хватает → дописать задание и переснять только недостающее.

## 4. Что делать с результатом
1. Положить файлы в `tests/fixtures/htm/<дата>/` (в репозиторий — только очищенные).
2. По `htm-adapter-spec.json` заполнить конфиг адаптера и `provider_rules` / `provider_message_map`.
3. Собрать или обновить стенд (скилл `htm-mock-stand-adapter`).
4. Обновить документ «архитектура и база» (раздел ХТМ, открытые вопросы).
5. Хэш структуры формы входа и формы показаний → эталон для канарейки.
