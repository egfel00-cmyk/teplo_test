# Теплосервис — данные на всех устройствах, вход, защита, распознавание по фото (01.11.2026)

## 1. Задача
Человек открывает сервис с телефона у счётчика, с компьютера дома и из Telegram-бота — и везде видит **свой** счётчик, базу и историю. Вход не должен пугать: сервисом можно пользоваться сразу, а сохранить в аккаунт — когда появилась ценность.

## 2. Решение: «сначала локально» + аккаунт
- Данные всегда сначала в браузере — сайт работает без сети и без входа.
- Есть аккаунт → изменения уходят на сервер (через 1,2 с паузы), другие устройства подтягивают их при открытии и раз в минуту.
- **Слияние** (`web/src/sync.js`, 8 тестов): показания объединяются по id (побеждает более новое изменение — например, «прийнято»); база «последних принятых» — с более поздней датой; «видалити все» побеждает старые записи; язык, тестовая дата и прочее локальное не синхронизируется.
- **Конфликт** (два устройства записали одновременно): сервер отвечает `409` со своей версией → клиент сливает и пишет снова. Ничего не теряется.

## 3. Где хранится
| Где открыт сайт | Хранилище | Вход |
|---|---|---|
| Свой сервер на NAS (боевой) | MariaDB, таблица `user_state` (JSON + версия) | Telegram или email + пароль (репозиторий teplo_test) |
| Опубликованный прототип на claude.ai | личный документ `data/users/<id>/teplo` (закрыт даже от владельца страницы) | аккаунт Claude — сам |
| Файл `index.html` без сервера | только браузер | — |

Прототип на claude.ai синхронизируется уже сейчас — можно проверить «телефон ↔ компьютер» на себе. Для настоящих пользователей — только свой сервер.

## 4. Вход
- **Из Telegram-бота:** кнопка «Теплосервіс» (меню бота и /start) открывает сайт как Mini App. Вход происходит сам — сайт отдаёт серверу подписанные Telegram данные (`initData`), сервер проверяет подпись токеном бота. Ни экрана входа, ни пароля. Язык — из Telegram.
- **По прямому адресу:** регистрации на входе нет. Рядом с «Почати» есть «Вже користуєтесь? Увійти». После первых показаний на главной появляется мягкое «Збережіть показання в акаунті…» (можно отложить).
  - экран «Вхід»: **Через Telegram** (Login Widget, один тап) или **email + пароль**; «Продовжити без входу» всегда есть;
  - при первом входе всё, что человек уже ввёл в этом браузере, переносится в аккаунт.
- **Один аккаунт:** Telegram на сайте = тот же аккаунт, что в боте. К аккаунту из Telegram можно добавить email+пароль, к аккаунту с паролем — привязать Telegram (Налаштування).
- **Выход** на чужом устройстве убирает данные из браузера, в аккаунте они остаются.
- Ещё нет: восстановление пароля по почте (нужен PHPMailer) — до этого «забыл пароль» решается входом через Telegram.

## 5. Защита (подробно — `README.md`)
- **DDoS — сетью:** Cloudflare Tunnel (`cloudflared` на NAS) — без открытых портов на роутере, домашний IP скрыт, HTTPS и фильтрация трафика у Cloudflare; правило rate limiting на `/api/auth/*`, Bot Fight Mode, при атаке — Under Attack mode. Сам NAS DDoS не выдержит, и обещать обратного нельзя.
- **Приложение:** лимиты по IP и аккаунту (5 неверных паролей → 15 минут блокировки; 10 попыток входа за 5 минут с IP; 120 запросов/мин с IP), лимит размера запроса, сессии с HttpOnly/Secure/SameSite cookie и хранением только хэша токена, CSRF, одинаковое время ответа, проверка подписей Telegram, секрет вебхука, журнал входов. Проверено 31 тестом сервера + сквозным тестом в браузере.

## 6. Распознавание по фото
- Экран «Розпізнати з фото»: человек выбирает **сразу много фото** (экраны после каждого нажатия, можно добавить наклейку). Нейросеть с поддержкой изображений возвращает:
  - модель (из каталога) и номер;
  - все 10 полей с уверенностью;
  - на каком фото какое поле;
  - качество фото (блик, далеко, размыто).
- Подсказки модели: каталог моделей, порядок экранов проверенной модели (Sharky 774), прошлые принятые значения — **только для здравого смысла, копировать их запрещено**.
- Результат — в поля нашей формы с миниатюрой фото у каждого поля. «Не знайдено», «перевірте» (уверенность < 0,75) и «різні цифри на фото» видны сразу. Дальше — обычная проверка «как робот ХТМ»; неуверенные поля становятся 🟡 «звірте з екраном».
- **Модель по фото:** на экране выбора счётчика есть «Визначити модель за фото» — модель и единица подставляются сами.
- Фото не сохраняются, сохраняются только цифры.
- **Прототип:** распознаёт Claude через возможность страницы (`sample` с картинками). Первый раз спрашивает разрешения у человека.
- **Боевой сервер:** тот же промпт (`web/src/recognize.js`) через vision-API на сервере (`POST /api/recognize`, следующий шаг):
  - ключ API на NAS, фото удаляются сразу после ответа, согласие — галочкой перед первым распознаванием;
  - лимит 20 фото за раз и N распознаваний в день на бесплатном тарифе (стоимость — центы за пачку).
- Распознавание прямо на устройстве (WASM) оставлено как исследование: семисегментные экраны с бликами модели в браузере читают ненадёжно.

## 7. Что проверено
- `web/tests/sync.test.js` — 8 проверок слияния.
- `tests/server.php` — 39 проверок: подписи Telegram, вход, CSRF, два устройства, конфликт версий, один аккаунт на Telegram и пароль, блокировки, реальный IP за Cloudflare, бот, загрузка фото сырым телом и распознавание.
- Сквозные тесты в браузере:
  - **сервер:** регистрация на компьютере → вход на телефоне → те же счётчик и база; 6 неверных паролей → блокировка; «открыто из Telegram» → вход сам, язык из Telegram;
  - **прототип с имитацией claude.ai:** 7 фото → все 10 полей; поле с бликом → «перевірте»; показание видно на втором устройстве; «прийнято» с одного устройства видно на другом.
